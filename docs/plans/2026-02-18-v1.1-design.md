# BatchCropper v1.1 — Design Document

**Date:** 2026-02-18
**Scope:** Four quality-of-life features from the v1.1 roadmap
**Approach:** Option B — enrich `files[]` entries, build features on top

---

## Features in Scope

1. Aspect Ratio Lock
2. Keyboard Shortcuts
3. Per-file Crop Override
4. Image Info Display

---

## State Changes (Foundation)

### `files[]` entry shape

Each entry grows two new fields:

```js
{
  file: File,        // original File object
  done: false,       // marked true after export
  crop: null,        // null = use batchCrop; {x,y,w,h} = file-specific override
  info: null,        // null until loaded; {w, h, size} once known
}
```

### Batch crop variable rename

`cropRect` is renamed to `batchCrop`. It remains the shared default applied to all files
that have no override.

The _active_ crop (what inputs and the crop box display) is computed as:

```js
files[activeIndex].crop ?? batchCrop;
```

### Edit routing

- If `files[activeIndex].crop` is non-null → drag and input edits write to that object.
- Otherwise → edits write to `batchCrop`.

This means editing without saving an override always modifies the batch default,
preserving the existing mental model.

### Export

Each file is cropped using `file.crop ?? batchCrop`.

## Feature 1: Aspect Ratio Lock

### UI

A `<select>` element added to the **Crop Region** sidebar section, below the X/Y/W/H inputs:

```
Ratio: [ Free ▾ ]   options: Free, 1:1, 4:3, 3:2, 16:9, Custom
```

When **Custom** is selected, two small `<input type="number">` fields appear inline
for the W and H ratio values (e.g. `7` and `5`).

### State

```js
let aspectRatio = null; // null = free; number = W/H ratio (e.g. 16/9)
```

### Constraint logic

Applied inside the `mousemove` handler after computing raw `w` and `h`:

| Drag mode                               | Constraint applied                       |
| --------------------------------------- | ---------------------------------------- |
| `new`                                   | `h = w / aspectRatio`                    |
| Corner handles (`tl`, `tr`, `bl`, `br`) | `h = w / aspectRatio`                    |
| Edge handles (`tm`, `bm`, `ml`, `mr`)   | None — single-axis intent is unambiguous |
| `move`                                  | None — moving does not resize            |

### Existing crop on ratio change

Selecting a ratio does **not** modify the existing crop. Constraint applies only to
subsequent drag operations.

## Feature 2: Keyboard Shortcuts

### Listener

A single `keydown` listener on `document`. Ignored when
`event.target` is an `<input>` or `<select>` (to avoid interfering with typed values).

### Bindings

| Key           | Action                                           |
| ------------- | ------------------------------------------------ |
| `ArrowLeft`   | Nudge crop X −1px                                |
| `ArrowRight`  | Nudge crop X +1px                                |
| `ArrowUp`     | Nudge crop Y −1px                                |
| `ArrowDown`   | Nudge crop Y +1px                                |
| `Shift+Arrow` | Nudge by 10px                                    |
| `R`           | Reset crop (equivalent to clicking Reset button) |

Arrow keys call `preventDefault()` to suppress page scroll.

After each nudge: clamp crop to image bounds, update inputs, update crop box visual.
Nudging writes to the active crop (file override or batchCrop, per edit routing above).

## Feature 3: Per-file Crop Override

### UI additions

**In the Crop Region sidebar section:**

- `[Save for this file]` — ghost button below Reset. Saves a copy of the current active
  crop into `files[activeIndex].crop`. Now this file diverges from the batch default.
- `[Clear override]` — ghost button, visible only when the active file has an override.
  Removes `files[activeIndex].crop` (sets to `null`), restores batch default display.

**In the file list:**

- Files with a saved override show a small `◈` badge after the filename.

### Switching files

`showPreview(i)` loads the effective crop for file `i` into the active view:

```js
const activeCrop = files[i].crop ?? batchCrop;
// set inputs and crop box to activeCrop
```

If the file has an override, the inputs/box show that override. If not, they show the
batch default. In both cases the displayed crop is immediately editable.

### Override vs batch distinction

There is no visual mode indicator beyond the `[Clear override]` button being visible.
The user knows a file is overridden because the button is present and the `◈` badge
appears in the list.

## Feature 4: Image Info Display

### State

Stored in `files[i].info`:

```js
{
  w: number,    // natural width in pixels
  h: number,    // natural height in pixels
  size: number, // file.size in bytes
}
```

`file.size` is populated immediately on load (synchronous). Natural dimensions are
populated when the image is first previewed, and also via a lightweight background
pre-loader that runs after files are loaded.

### Background pre-loader

After `loadFiles()` completes, a sequential background loop loads each file's image
into a temporary `Image` object to extract `naturalWidth` / `naturalHeight`, then
re-renders the file list. It runs one image at a time to avoid memory spikes.

### UI

Each file-list item gains a subtitle line in dim monospace below the filename:

```
photo.jpg
1920 × 1080 · 2.4 MB
```

Before dimensions are known: `··· × ··· · 2.4 MB` (size is always known immediately).

### Formatting

- Dimensions: raw integers, `×` separator
- Size: formatted to one decimal place with appropriate unit (KB / MB)

## Architecture Constraints

This is a single HTML file with no build step. All changes stay within `index.html`.
No new external dependencies are introduced. The JSZip CDN load on export is unchanged.
