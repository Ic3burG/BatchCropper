# BatchCropper v1.3 — UX Polish Design

Date: 2026-02-19
Status: Approved

---

## Overview

Three features completing the v1.3 UX Polish milestone:

1. **Undo/Redo** — step back through crop region changes
2. **Touch Support** — drag, pinch-to-zoom, and swipe file navigation for tablet use
3. **Persistent Settings** — remember export format, quality, filename template, aspect ratio, and zoom via `localStorage`

All features are implemented inside the existing single `index.html` file with no build toolchain or external dependencies.

---

## Feature 1: Undo/Redo

### Approach
Snapshot array with a cursor (historyIndex pointer).

### State
```js
let cropHistory = [];   // array of {x, y, w, h} snapshots
let historyIndex = -1;  // points to current position in history
const HISTORY_LIMIT = 50;
```

### `pushHistory()`
- Truncates `cropHistory` forward of `historyIndex` (discards redo stack on new edit)
- No-op if the new snapshot is identical to the current entry
- Appends `{...activeCrop}` to the array
- Caps array at `HISTORY_LIMIT` entries (shifts oldest off the front)
- Increments `historyIndex`

### When to push
| Event | Location |
|---|---|
| Drag complete | `pointerup` handler |
| Arrow key nudge | `keydown` handler (after applying move) |
| Reset (R key or Reset button) | `keydown` + reset button click |
| Numeric input committed | `change` event on `inX/inY/inW/inH` (not `input`) |
| Save/Clear override | respective button click handlers |

### Undo/Redo shortcuts
- `Ctrl+Z` → undo (move `historyIndex` back, restore snapshot)
- `Ctrl+Shift+Z` and `Ctrl+Y` → redo (move `historyIndex` forward, restore snapshot)
- Both skip when focus is on `INPUT` or `SELECT`
- Both call `updateInputs()` + `updateCropBoxVisual()` after restoring

### History reset
`cropHistory = []; historyIndex = -1;` on:
- `loadFiles()` — new file batch loaded
- `clearFiles()` — workspace cleared
- `showPreview(idx)` — switching to a different file (activeCrop changes object)

## Feature 2: Touch Support

### Approach
Replace all mouse event listeners with Pointer Events API; add pinch-to-zoom via dual pointer tracking; add swipe-to-navigate on the file list.

### Pointer Events refactor
- `mousedown` → `pointerdown`
- `mousemove` → `pointermove`
- `mouseup` → `pointerup`
- Handler logic is unchanged
- Call `e.target.setPointerCapture(e.pointerId)` on `pointerdown` to retain capture through the full drag gesture (replaces the current `document`-level `mousemove` approach)

### Pinch-to-zoom
Track active pointers in a `Map<pointerId, {x, y}>` on `previewContainer`:
- On second `pointerdown`: record `pinchStartDist` (distance between two pointer positions) and `pinchStartZoom`
- On `pointermove` with 2 active pointers: compute new distance, derive scale factor vs `pinchStartDist`, apply to `pinchStartZoom`, clamp to `[0.05, 8]`, call `applyZoom()`
- Skip single-pointer drag logic while 2 pointers are active

### Swipe file navigation
`touchstart`/`touchend` listener on `#file-list`:
- On `touchstart`: record `touch.clientX` and `touch.clientY`
- On `touchend`: compute `deltaX` and `deltaY`
- Trigger only if `|deltaX| > 40` and `|deltaY| < 60` (prevents false-positives during vertical scroll)
- Left swipe (`deltaX < -40`) → next file; right swipe (`deltaX > 40`) → previous file
- Calls `showPreview()` + `renderFileList()`

## Feature 3: Persistent Settings

### Approach
Centralized `saveSettings()`/`loadSettings()` pair with a single `localStorage` key.

### Storage key and schema
Key: `batchcrop_settings`

```json
{
  "format": "image/png",
  "quality": 0.95,
  "filenameTemplate": "{name}_cropped",
  "ratioSelect": "free",
  "ratioW": 16,
  "ratioH": 9,
  "zoom": 1
}
```

### `saveSettings()`
Reads from variables and DOM elements, writes JSON. Called from:
- `export-format` change handler
- `export-quality` input handler
- `filename-template` input handler
- `ratio-select` change + `ratio-w`/`ratio-h` input handlers
- `zoom-in`, `zoom-out`, `zoom-fit` click handlers (after `applyZoom()`)

### `loadSettings()`
Called once at script startup (bottom of `<script>`, after all elements declared). Wrapped in try/catch; falls back silently if key is missing or JSON is malformed.

Restores:
- `export-format` value → manually fires visibility logic for `qualityContainer`
- `export-quality` slider value + `qualityVal` span text + `exportQuality` variable
- `filename-template` input value + `filenameTemplate` variable
- `ratio-select`, `ratio-w`, `ratio-h` values → calls `updateAspectRatio()`
- `zoom` variable (applied on first image load via `applyZoom()`, not immediately)

### Intentionally not persisted
- File list, crop region, active file index (session-specific state)
