# v1.8 — Rotation Handle: Design Document

**Date:** 2026-02-26
**Status:** Approved

---

## Overview

Add a rotation handle to the crop box so users can rotate the crop selection before export. The output is always a clean rectangle — the image is rotated to match the crop box at export time (the "horizon correction" / Lightroom Straighten model). The image itself is never permanently modified.

Two input methods: a drag handle on the canvas for tactile control, and a numeric input + slider in the sidebar for precision.

---

## Data Model

Rotation is stored as a number in degrees (−180 to +180) on the crop object:

```js
// crop object (before)
{ x, y, w, h }

// crop object (after)
{ x, y, w, h, rotation: 0 }
```

Both `batchCrop` and per-file `files[i].crop` include `rotation`. A parallel global mirrors the flip pattern:

```js
let cropRotation = 0; // degrees, -180 to +180
```

Undo/redo captures `{ ...activeCrop }` already — `rotation` rides along for free.

## UI Components

### Rotation drag handle (canvas area)

A new `<div id="rotation-handle">` positioned relative to the same parent as `#crop-box`. Rendered as a small circle (matching existing handle style) with a short vertical stem connecting it to the top edge of the crop box.

- Positioned by JS in `updateCropBoxVisual()`: centered horizontally above the crop box at a fixed 28px offset above the top edge
- Cursor: `grab` / `grabbing`
- The stem rotates with the crop box using the same `transform: rotate(${cropRotation}deg)` anchored at the stem's bottom

### Sidebar controls (inside existing Crop section)

A new row inside the existing collapsible Crop section, between the coordinate inputs and aspect ratio controls:

```
Rotation  [ -12.5 °]   [←→ slider -180..+180]   [⟳]
```

- Numeric input (step 0.1°) and slider (step 0.5°) kept in two-way sync — same pattern as the quality slider
- Reset button (⟳) snaps to 0°
- No new section; lives inside the existing Crop collapsible

## Interaction

### Rotation drag handle

On `pointerdown` on `#rotation-handle`: capture the pointer, record the crop box center in screen coordinates and the angle from center to cursor at drag start.

On `pointermove`: compute the new angle from center to cursor, apply the delta to the rotation at drag start, clamp to −180…+180. Snap to 0° within ±2° to make it easy to find level:

```js
const angle = Math.atan2(cursor.y - center.y, cursor.x - center.x) * (180 / Math.PI);
cropRotation = clampAngle(startRotation + (angle - startAngle));
if (Math.abs(cropRotation) < 2) cropRotation = 0; // snap to level
```

A new `dragMode = 'rotate'` is added alongside the existing move/resize modes to avoid collision with existing logic.

### Existing handle pointer events — coordinate un-rotation

When `dragMode` is `move` or a resize handle and `cropRotation !== 0`, pointer deltas must be un-rotated before being applied to `activeCrop`:

```js
const rad = (cropRotation * Math.PI) / 180;
const dx_img = dx * Math.cos(-rad) - dy * Math.sin(-rad);
const dy_img = dx * Math.sin(-rad) + dy * Math.cos(-rad);
```

This slots into the existing `pointermove` handler where `dx`/`dy` are currently used directly (~6 lines).

## Preview & Visual Feedback

### Crop box rotation

`updateCropBoxVisual()` gains one line:

```js
cropBox.style.transform = `rotate(${cropRotation}deg)`;
```

The 8 resize handles and grid overlays rotate with it for free as children of the div.

### Rotation handle positioning

```js
const cx = sx + sw / 2; // center of crop box in screen pixels
const ty = sy - 28; // 28px above top edge (before rotation)
rotationHandle.style.left = `${cx}px`;
rotationHandle.style.top = `${ty}px`;
```

### Overlay masks

When `cropRotation !== 0`, skip the 4 rectangular mask divs. Fall back to reducing `previewImg.style.opacity` to 0.6 — honest about the rotated region without complex polygon geometry. Masks restore to normal when rotation returns to 0°.

### Coordinate display

The canvas toolbar coords display appends `R: ${cropRotation.toFixed(1)}°` when rotation is non-zero.

## Export

### The math

Output canvas is sized to `crop.w × crop.h` (unchanged). The image is rotated on the export canvas to undo the crop box rotation:

```js
if (cropRotation !== 0) {
  const rad = (-cropRotation * Math.PI) / 180;
  const cx = crop.w / 2;
  const cy = crop.h / 2;

  ctx.translate(cx, cy);
  ctx.rotate(rad);
  ctx.drawImage(img, -(crop.x + cx), -(crop.y + cy), imgNatW, imgNatH);
} else {
  ctx.drawImage(img, crop.x, crop.y, crop.w, crop.h, 0, 0, crop.w, crop.h);
}
```

### Flip + rotation

When both are active, apply flip transforms first, then rotate — matching the existing convention (flip is already applied before `drawImage`).

### Shared helper

Extract `drawCroppedImage(ctx, img, crop)` from the three currently-duplicated export paths (batch ZIP, single download, copy to clipboard). All three call the helper. This also ensures the compare view (v1.7) picks up rotation in its after-panel rendering.

## Edge Cases

| Case                        | Behaviour                                                               |
| --------------------------- | ----------------------------------------------------------------------- |
| Undo/redo                   | `rotation` is part of the crop object snapshot — captured automatically |
| Per-file crop               | `rotation` saved with the per-file override; restored on file switch    |
| Aspect ratio lock           | Orthogonal — both can be active simultaneously, no conflict             |
| Compare view                | Uses `drawCroppedImage()` helper; rotation appears in the after-panel   |
| Reset crop button           | Also resets `cropRotation = 0` and updates sidebar input/slider         |
| Keyboard nudge (arrow keys) | Operate on `x/y` in un-rotated space — no change needed                 |
